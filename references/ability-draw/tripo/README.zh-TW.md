# 蒙面NPC／抽獎機：三視圖與Tripo交接

2026-11-11，使用者要求以最早九格分鏡中的造型製作嚴謹三視圖，供自行以Tripo生成3D。三張均為ImageGen建模設計稿；已按正／側／背、共用高度基準、近似正交視角及簡單背景生成並檢視，**不是由同一精確CAD／3D模型投影出的工程圖**。原片未展示完整背面，背面是依正面造型補完；生成模型後仍須校正比例、結構與活動件。

## 檔案用途

- `dealer-three-view.png`：蒙面NPC，正面／朝右側面／背面，中立A-pose，張開全指手套、無道具，便於生成後綁骨。
- `machine-assembled-three-view.png`：抽獎機完整外觀，正面／拉桿側／背面，用於核對造型與組裝；**不建議直接生成一整件可動機器**。
- `machine-shell-three-view.png`：建議給Tripo的外殼版本。移除輪盤、輪子、拉桿，輪盤窗口留空，保留固定機殼／喇叭／燈條／出貨口框與接物盤。出貨口上方橙色遮簷視為固定件；另外建立真正開合的內側出貨蓋，避免誤認圖中的固定遮簷已是獨立活動零件。
- `npc-prompt.txt`、`machine-shell-prompt.txt`：可複製使用的英文生成規格，不含服務端生成參數或付費操作。
- `manifest.json`：圖片尺寸、來源及SHA-256。原始生成圖另外保留於本聊天生成目錄。

若使用的Tripo入口支援多視角，先把三視圖裁成正／側／背三張，按對應視角上傳；只支援單圖時，以正面作主要輸入，不把整張含三個身影的排版直接視為單視角照片，避免生成三個黏連的物件。具體可用入口與多視角支援依使用者所用版本確認，本輪未聲稱已測試Tripo服務。

## 機器是否適合Tripo

首選是手工硬表面建模：機器以方箱、簡單斜面、圓柱為主，容易控制窗口、輪軸和pivot，對精準動畫更穩定。已有Godot程序模型可供比例與機構參考，但其外觀並非這張設計稿的精確模型。

如果偏好Tripo，採混合製作：只用Tripo做靜態機殼／磨損與大色塊風格，再以乾淨幾何製作活動件。不假設Tripo輸出保有獨立物件、正確圓柱、空洞或輪軸。

| 部分 | 建議製作方式 | 動畫要求 |
| --- | --- | --- |
| 機殼、固定喇叭、固定接物盤 | 手工首選，或Tripo外殼後整理 | 整機拖行、傾斜、拍擊回彈，由父節點控制。 |
| 三個輪盤 | 手工三個獨立圓柱＋可替換圖示貼圖 | 各自圍繞水平軸旋轉／減速／準確停在結果，窗口需真有深度。 |
| 四個輪子 | 手工，獨立輪軸；必要時caster支架分開 | 依路程轉動，輪徑及接地高度可校正。 |
| 拉桿 | 手工獨立槓桿／把手 | 以側面pivot轉動，不使用外殼上的畫出來把手。 |
| 出貨蓋 | 手工獨立薄板，與固定遮簷分清 | 鉸鏈開合、與出貨筒不穿模。 |
| 能力筒／代幣 | 獨立小道具 | 自由彈出、接住／展示、未來安裝socket切換。 |

整台Tripo模型做拖行／震動並不難：可當剛體式父節點動作，不要求骨骼。真正增加成本的是「部件黏連或只是貼圖」卻要各自轉動；如已有整台模型仍能拆件／切開窗口／重建輪盤，不代表動畫無法完成，但工時與可控性較差。

## 後續接入原則

保留原GLB／貼圖，衍生版本再清理。NPC檢查手指、腋下、衣袖、髖部可用拓撲；靜態模型須補骨架與權重，再做拖行、煞停、拍機、代幣展示及爆獎反應。機器用父子節點／獨立pivot，不必為每個剛性零件做角色式skin rig。依Tripo模型實際尺寸校正接觸點、輪徑與鏡頭；不要把本圖當已驗證的實際公尺標尺。

此次只有生成參考圖與製作建議，沒有收到或生成新的Tripo模型，未改遊戲runtime、未替換原角色／機器，也未發佈Web。
