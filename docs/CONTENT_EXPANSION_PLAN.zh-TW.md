# 玩法與創意擴充企劃：故事先行、解鎖自由對戰、本機雙人

2026-11-11。回應使用者四項要求：（1）遊戲開始只有故事模式，通關後解鎖自由對戰；（2）同一電腦鍵盤雙人對打；（3）雙手柄；（4）詳細豐富玩法與創意 idea。

**本文件是企劃，不是實作報告。** 沒有改動遊戲程式、存檔、傷害／能量／Rush／SURGE 規則或公開 Web。已實作現況以 [LAST_SERVICE_RUNTIME.zh-TW.md](LAST_SERVICE_RUNTIME.zh-TW.md)、[LIVE_COMBAT_IMPROVEMENTS.zh-TW.md](LIVE_COMBAT_IMPROVEMENTS.zh-TW.md) 為準；下文「現況」皆來自讀取 repo 檔案與 `scripts/combat/` 程式碼，未在本輪實機執行遊戲。

## 0. 指導原則

1. **改善正式遊戲，不做獨立原型**（AGENTS.md 最新使用者更正）。所有切片都接入 `FIGHT`／`STREET RUN` 正式流程；不再新增只存在於 F 鍵教室的玩法。
2. **沿用既有 owner**：pressure／SURGE、Rhythm、Neon 各只有一個 owner；劇情與模式只提供「情境」，不裁決傷害。
3. **標準對戰固定數值**：成長／解鎖只改外觀、演出與 Street Run；自由對戰、雙人固定公平規則（延續 RPG 提案的公平原則）。
4. **音樂不停、UI 文字與數字走原生、封面無臉無項鍊、不覆寫原始 GLB。**
5. 新資產（角色、場景、音樂）需 Alan 提供或明確授權；付費生成先給參考圖與規格。
6. 無法聲稱：真人手感、平衡、Mac 硬件、實聽、雙手柄實機皆需 Alan 本機驗收（見 §9）。

## 2. 模式結構與解鎖流程

### 2.1 選單門檻（需求 1）

首次啟動：

```
STORY（唯一可選）   FIGHTERS（只看／配搭，不能開戰）   SETTINGS   HOW TO PLAY（含 C 教學）
 ░ FREE FIGHT      （鎖）  ← 顯示「完成故事解鎖」
 ░ VERSUS 2P       （鎖）
 ░ TRAINING        （鎖或保留？見決策點 D1）
 ░ AI DEMO         （鎖，解鎖後出現）
```

- 鎖定項目仍顯示在主選單，但灰階＋鎖圖示＋一行解鎖條件；按下只提示條件，不彈窗。目標是讓玩家**知道有後續**。
- 解鎖旗標存於獨立 `user://neon_lab/story.cfg`（schema version、`story_cleared`、各章星級、已見過的過場），**不覆寫 options.cfg 與 progression.cfg**；損壞時退回「未通關」而非崩潰。
- 「通關」定義：打完最終章 Boss 並看過結局（不是只開始）。通關當下彈一次性的「FREE FIGHT／VERSUS 已開放」通知與音效；之後永久解鎖。
- **老玩家保護**：Alan 與測試者已有存檔。提供 `SETTINGS → 解鎖全部（測試用）`，以及命令列／環境旗標 `--unlock-all`，避免每次驗證都要通關。這個後門只改旗標，不給 XP／成就；列入驗證文件。
- 教學：首分鐘四課（C）改為故事 **序章**內嵌，也保留獨立入口，不被鎖。

### 2.2 決策點（需 Alan 確認）

| # | 問題 | 建議 | 備選 |
|---|---|---|---|
| D1 | TRAINING 也鎖嗎？ | **不鎖**，放進故事序章後解鎖（教學用途） | 與 FREE FIGHT 同鎖；或一開始就開 |
| D2 | 通關門檻是否按難度？ | Normal 以上通關即可解鎖，Easy 也算（避免卡關） | 只認 Normal+ |
| D3 | 角色是否也逐步解鎖？ | 開局只有 ZIP，故事推進送出其餘三位（天然的教學與動機） | 四人一開始全有 |
| D4 | 雙人是否與 FREE FIGHT 同時解鎖？ | 同時解鎖，避免兩套門檻 | 雙人更早開放（朋友來了很需要） |

> D3 對現有「選角頁、Street Run、Demo」影響最大：未解鎖角色在選角頁顯示剪影＋解鎖條件，Demo 與 AI 對手不受限。

## 3. 故事模式：把 Street Run 升級為章節式劇情

**目標：** 3 站 → 5 章＋序章，每章約 8–15 分鐘，由「過場文字／漫畫格」＋「2–3 場真對戰」＋「章末 Boss 或特殊規則戰」組成。劇情不增加新戰鬥規則，只調整**情境、對手資源與規則包裝**，保證能用現有 `FIGHT` 引擎完成。

### 3.1 世界觀骨架（沿用 LAST SERVICE／港式低空航道街區）

- 設定：深夜末班之後，低空航道街區的最後一班夜間服務（電車／配送／電台）即將停運；四人各自守著一個「最後的服務」。
- 主題：**把最後一班送到站**。對手不是單純壞人，而是不願讓街區停運或想趁停運佔地的人。
- 語氣：JSR 式叛逆＋港式生活感；繁中為主、英文為輔（沿用現有語言切換）。文字量要小：每段過場 ≤ 6 句，每句 ≤ 20 字，方便原生 UI 與 24／28 字級。

### 3.2 章節表（草案）

| 章 | 名稱（暫） | 地點／場景 | 對手與規則包裝 | 教學／解鎖 | 工作量 |
|---|---|---|---|---|---|
| 序 | 收工後 | 街口、斑馬線 | 沿用 C 首分鐘四課，包成「老闆教你送件」 | 解鎖 TRAINING（D1） | S |
| 1 | 頭班之前 | 巴士站＋小食店 | 街頭混混 ×2；第 2 場規定「必須用連段打出 BREAK」 | 送出 RIVET（D3）；教連段／格擋 | M |
| 2 | 低空航道 | 高架下、飛機掠過場景（已有 aircraft_flyby） | CPU 頻繁挑空；章中規則：場邊反彈＝額外分 | 送出 HUSH；教空戰／追擊 | M |
| 3 | 霓虹電台 | 地下電台入口、霓虹加強 | 精英對手使用 SURGE 高壓；觀眾（背景演員）呼應 | 送出 LOOP；SURGE 三階首次完整出現 | M |
| 4 | 停運公告 | 全街區夜景、雨天或霧 | 雙對手車輪戰（兩回合 HP 不回滿） | 教資源管理 | M |
| 5 | 末班 | 終點站／天台（新場景，需 Alan 授權美術） | Boss：以現有 4 人招式組合的「混合型」AI，加專屬大招演出 | 通關；解鎖 FREE FIGHT／VERSUS／AI DEMO；顯示結局 | L |

### 3.3 戰鬥外的故事呈現（低成本優先）

1. **漫畫格過場**：沿用現有 Ink UI 素材風格，單格 640×360 靜態圖＋文字＋少量鏡頭平移；所有文字原生繪製（不烘焙文字進圖）。每章 3–5 格。
2. **戰前對話條**：HUD 的 VS 畫面加兩句「叫陣」台詞（每人 6–8 句，隨章節輪換）。
3. **戰中小事件**：低血量時對手說一句話（單句氣泡，可關）；Boss 階段變化以既有 Rhythm／Neon 演出，不新增判定。
4. **章節結算**：重用 Street Run 結算畫面，增加星級（時間／BREAK 數／受傷）與一句「街區回應」文字，XP 沿用 `progression.gd` 規則（Demo／fixture 不給獎）。

### 3.4 規則細節與風險

- 劇情對戰**沿用標準規則**；章節「特殊規則」僅選擇性加成（例：場邊反彈額外計分），且在 HUD 明確顯示。
- 失敗時保留章節進度，可重試；第三次失敗提供「降低一級難度」提示（不強迫、不扣星）。
- 存檔：以「章＋戰」為單位；中途退出回到該戰開頭，不保存半場狀態。
- 風險：劇情量大。**最小可玩版本（MVP）**＝序＋1＋5 章（直接序章→一章→Boss），其餘章節逐步補入，每補一章不改解鎖邏輯。

## 4. 本機雙人對打（同一鍵盤）

### 4.1 現況與可行性

模擬層 `tick(player, opponent)` 已能同時吃兩份指令；`fight_session.gd` 以硬寫的 `Input.is_physical_key_pressed` 組裝玩家指令，目前的 P1 鍵位為 **A/D 移動、W/S、Space 跳、J 輕、K 重、L 爆發、Shift 防禦、E 滾動**（左右方向鍵目前也綁了移動）。要做雙人，需要：

1. 把「鍵位→指令字典」抽成**輸入來源**（`InputSource`：Keyboard／Gamepad／AI），每方一個。
2. P2 的指令字典由第二個輸入來源提供；`ai_command` 只在 P2 為 AI 時使用。
3. 事件型輸入（pending buffer、`guard_pressed`、連段／預輸入、SURGE 逐邊鎖定的 J／Shift／E）**必須分玩家**：目前 `_unhandled_input` 多處用全域 `event.keycode`，要改成「哪個來源觸發」。

> 這是此需求中最容易漏改的部分：SURGE 意圖鎖定、友善防禦、空中選擇（`commit_air_choice`）原本都只認 P1。

### 4.2 鍵位草案（單鍵盤雙人）

| 動作 | P1（左手區） | P2（右手區） | 備註 |
|---|---|---|---|
| 移動 | A / D | ← / → | |
| 向上／向下（挑空／急降修飾） | W / S | ↑ / ↓ | |
| 跳 | Space（保留） | Right Ctrl（或 Enter） | 二段跳需「放開再按」，兩個鍵都要能偵測 |
| 輕（J 位） | J | Numpad 1（或 `/`） | |
| 重／挑空（K 位） | K | Numpad 2 | |
| 爆發（L 位） | L | Numpad 3 | |
| 防禦 | Shift（左） | Right Shift | 注意：兩個 Shift 在多數引擎中分左右需用 `physical_keycode` |
| 翻滾／抽身 | E | Numpad 0（或 `.`） | |

設計重點：
- **鍵位可重綁**，預設兩組；設定頁顯示衝突提示。
- **鍵盤幽靈鍵（ghosting）**：雙人同時按多鍵時，便宜鍵盤可能丟鍵。企劃中加入「輸入測試頁」（按鍵即亮），讓玩家先測各自區域；P2 若無數字鍵盤（筆電）提供「P2 備用組：I/O/P＋方向鍵」預設。
- **無法聲稱的內容**：實際幽靈鍵情況取決於硬件，不能在雲端驗證；列為 Alan 實機驗收項。

### 4.3 雙人模式規則（VERSUS 2P）

- **固定公平規則**：標準數值、不套 XP／技能裝備（與 RPG 提案一致）；兩方各自選角（可同角，沿用現有）。
- **勝負**：BO1／BO3／BO5 可選；時間限制／無限；預設 BO3。
- **血量／能量**：完全沿用現有。
- **鏡頭**：現有鏡頭以玩家為主；雙人要改為「雙方對稱構圖」，不偏向 P1。沿用 `Neon`／`Rhythm` owner，只新增「對稱模式」旗標。
- **UI**：HUD 左右對稱的 P1／P2 標示（顏色沿用陣營色，增加「1P／2P」標籤，避免只靠顏色，可及性）。
- **暫停**：任一方都能 Esc 暫停；只有發起者能恢復，避免誤觸（可選，列決策點 D5）。
- **SURGE 高壓選擇**：目前由 P1 的 J／Shift／E 逐邊鎖定。雙人時兩方都能鎖定，**不使用 AI 預承諾**（見 `docs/SURGE_WINDOW_PROTOTYPE.zh-TW.md` 的設計：逐邊首選、超時沿用原輸入）。
- **重賽**：結算畫面「Rematch／換角／回選單」，優先減少來回選單。
- **平衡**：雙人會暴露單機 AI 看不出的問題（如 spam、角色強弱）；列為上線後的平衡備忘，不宣稱已平衡。

## 5. 雙手柄（需求 3）

### 5.1 現況

專案**沒有任何手柄支援**，也沒有自訂 InputMap。需要新建手柄輸入來源。以 Godot 4 的 `Input` 與 `Input.get_connected_joypads()` 為基礎（4.6.3／4.7.2 皆可），不依賴外掛。

### 5.2 預設手柄映射（Xbox 風格；PS／Switch Pro 使用同一標準映射）

| 動作 | 手柄 |
|---|---|
| 移動 | 左搖桿／十字鍵（死區 0.25，雙向都吃） |
| 向上／向下修飾 | 左搖桿上／下（或十字鍵） |
| 跳 | A（Cross） |
| 輕 | X（Square） |
| 重／挑空 | Y（Triangle） |
| 爆發 | B（Circle） |
| 防禦 | LB／L1（或 LT） |
| 翻滾／抽身 | RB／R1 |
| 暫停 | Start |
| 大招（W＋L 蓄力重砲） | RT＋B（或「上＋B」，沿用方向＋鍵的規則） |

要點：
- **指派規則**：先按任一鍵「入座」→ 依連接順序指派 P1／P2；可在選角頁調換。混合輸入（P1 鍵盤＋P2 手柄、雙手柄、雙鍵盤）都要支援，因此 `InputSource` 是每方獨立的。
- **熱插拔**：手柄中途拔掉 → 自動暫停＋提示「P2 手柄已斷線，插回或改用鍵盤」；不得讓角色失控或卡住 `guard`／移動（輸入全部歸零）。
- **UI 導覽**：選單／選角需要手柄方向鍵＋A／B 導覽，並顯示當前輸入裝置圖示（簡單文字提示即可：A／B vs Enter／Esc）。
- **死區與搖桿手感**：搖桿類比值轉成現有 `axis` 浮點（模擬層本來就用 `axis`），不加新移動速度規則。
- **按鈕與預輸入**：沿用現有 buffer 窗口；手柄的「按下事件」要走同一個 pending 流程，否則會出現鍵盤與手柄手感不一致。
- **單手柄也可玩單人模式**；選單提示不再只寫鍵位。
- 驗證現實：雲端無法接實體手柄。可用 Godot 的 `Input.parse_input_event`／合成 `InputEventJoypadButton`／`InputEventJoypadMotion` 做規則與映射測試，但**不等於實體手柄手感驗收**，須 Alan 本機接手柄試（雙人需兩支）。

## 7. 玩法點子池（沿用現有引擎）

## 8. 創意點子池

### 8.1 世界與敘事

- **「最後一班」收音機**：每章結尾 DJ 一段 15 秒廣播，口述街區反應；文字原生繪製，音效為已有 CC0／使用者提供音樂的 ducking，不新增音訊 transport。
- **街區居民 NPC**（背景演員）：已有五人群像與背景演員技術；觀戰時依連段回應（跳起、舉牌）。零判定，純氣氛。
- **傳單／塗鴉收集**：每章藏 3 個可見但不顯眼的塗鴉（圖片素材），集齊解鎖畫廊；畫廊＝藝術參考庫（references/style-library）的遊戲內入口。
- **反派動機三選一**：Boss 戰前根據玩家過往風格（連段／防守／空戰）插入不同兩句，純文字分支。

### 8.2 美術與音樂

- **風格切換濾鏡**（保持單 owner）：黑白＋桃紅、青粉、赤橙三套 palette，與角色 palette 解鎖互不衝突。
- **章節專屬調色**：每章低飽和度主色，轉場以 Neon／Rhythm owner 統一做；不另寫第二套轉場。
- **音樂層次**：同一曲子加／減層（低音、人聲 chop）隨 SURGE 階段變化；規則：**不停音樂，只 crossfade**（AGENTS.md）。
- **CC0 彩蛋曲**：每章解鎖 1 首（需先 admitted.json 登記，不擅自聯絡藝術家）。
- **像素化強度滑桿**：現有 640×360 統一 viewport 的「低解像」選項，擴為 3 檔。

### 8.3 彩蛋與驚喜

- 秘技輸入（本機）：在主選單輸入特定組合解鎖無害造型（例：全黑白濾鏡）。
- 特定地點的「站名牌」彩蛋（港式地名諧音，原創，不使用真實商標）。
- 連續打贏同一對手的 5 次，對手台詞改變（記數、純文字）。
- 「同角色鏡像戰」專屬 Boss 台詞：對上自己時說「你不是第一個送件的人」之類。
- 開發者留言牆：通關後可看製作筆記（可引用 docs 的「為什麼這樣做」，增加世界觀可信度）。

### 8.4 雙人專屬創意

- **雙人通關合作故事（Co-op，延後）**：P1／P2 並肩對 AI 群——需多人模擬，列長線，不在 P0。
- **輪流持機賽**：兩人同鍵盤、輸者讓出座位，結算界面顯示連勝；零新規則。
- **賽前賭注／規則轉盤**：每回合前轉出 1 個小規則（無投技、能量加倍…），沿用現有規則旗標；僅雙人自由模式。

## 9. 驗證與已知限制

- **可在雲端做**：規則／模擬單元測試（注入雙方指令、存檔 schema、解鎖旗標、斷線歸零）、headless 回歸（`verify.gd` 與既有 396／45／260 等檢查）、合成手柄事件映射測試、解析度截圖檢查。
- **不可在雲端宣稱**：真人手感、雙人平衡、鍵盤幽靈鍵、**實體手柄**手感與斷線行為、Mac 硬件、實聽混音。這些列為 Alan 本機驗收清單，驗收前文件標示「待驗證」。
- **回歸風險最高處**：`InputSource` 重構（P1 行為不能變）、SURGE／空中選擇的事件輸入分玩家、鏡頭對稱化。
- 每個切片依 AGENTS.md：決策寫入 `docs/DECISIONS.md`、進度進 `HANDOFF.md`／`TODO.md`、結果進 `VALIDATION.md`；來源推任務分支，公開 Web 只有 Alan 明確要求才更新。

## 10. 建議的實作順序

1. **P0-1＋P0-3 平行**：存檔／選單鎖定與 `InputSource` 重構（兩者互不依賴，風險最低先做）。
2. **V2–V4**：雙鍵盤雙人先於手柄（可立即驗證、決定鏡頭與 UI 的雙人形態）。
3. **G1–G3**：手柄套在已分玩家的輸入層上。
4. **P0-2 MVP 故事**（序＋1＋5）與解鎖串通；之後逐章補入。
5. P1 內容（章節補完、車輪戰、計分賽），再看 P2 點子池。

> 若想最快讓朋友能一起玩：順序可改為先 V2–V4（雙人）再做故事；但這與「開局只有故事模式」衝突，需要 D4 決定雙人是否更早開放。
