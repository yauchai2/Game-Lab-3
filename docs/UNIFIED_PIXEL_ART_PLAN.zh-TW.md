# 統一像素賽璐璐美術、街景生命感與 3D 選角計劃

2026-11-09。依最新使用者需求制定；**本文件為待實作規格，不代表以下功能已完成**。來源基線8ed0700。維持香港街口、五個英文主選項、四流派、友善防禦與持續音樂；公開Web仍須使用者另行要求才更新。

## 一、整體方向與現況差距

目標：**有清晰像素格的千禧年3D賽璐璐街鬥，配上塗鴉電台介面與有人生活過的香港街景。** 保留批准UI的橙／黃綠／深紫／奶油白、斜切字形、電台圓盤和四卡構圖，將其製成同一低解析規格，而非繼續混合高清插畫、平滑向量和低解析3D。

已核對現況：

| 範圍 | 已有實作 | 下一步差距 |
|---|---|---|
| 渲染 | retro_pixels shader在世界層取樣640×360；project仍1280×720 canvas_items | UI／VFX在其上高解析繪製；不是全畫面同一像素格 |
| UI | 主選單原圖、4卡、動態數值與參考布局 | 原圖細紋／插畫細節、向量、字體邊緣不一致；全圖底板限制獨立動畫 |
| 字體 | Barlow Condensed Black Italic＋現有正文 | 字標有態度，但一般文字還未成為同一家族的JSR像素字體 |
| 場景 | 可追溯街景裝飾與批次幾何 | 重複方塊、過齊窗列／植物、材質和輪廓仍欠手工差異 |
| 背景動態 | 天空約0.08°/秒漂移、飛機沿機頭方向循環 | 車仍主要停泊，缺乏路人／店舖／布篷的生活循環 |
| 特效 | 已移除生成貼圖；作者化6cel向量、4種爆發語言 | 仍在高清層，招式範圍與分層張力可再設計 |
| 選角 | 右側為平面立繪；實機四人已有不同動作／數值 | 選角右側尚非3D，卡片原畫大多同一遮臉拳架 |

本文件中的數字是本專案的起始規格與驗收目標，不當作已核實的JSR內部設定。先做代表切片，再決定批量製作。

## 二、統一像素格：先改渲染契約

### 2.1 建議基準

- 正式基準畫布640×360，16:9。世界、角色、VFX、UI、字體、3D選角都先在此規格合成，再以Nearest放大。
- 1280×720為2倍、1920×1080為3倍。所有描邊／光點／文字粗細按內部像素定義。
- UI可保留現有1280×720作者座標，但統一映射為2:1；不得讓VFX和文字繞過低解析合成。
- 任意視窗不能假稱永遠整數倍：像960×540相對640×360是1.5倍。以整數放大＋留邊作像素準確模式；填滿視窗可作選項，但需接受像素寬度不均。推薦測試與展示使用720p／1080p。
- 先對640×360與480×270做同場比較，**暫以640×360採用**。320×180只適合另作極低清實驗，容易犧牲人臉、腳位和設定可讀性。

### 2.2 Godot落地方式

優先原型化單一低解析遊戲viewport，使用viewport式縮放；或將整個遊戲UI／3D／VFX放入同一SubViewport後Nearest合成。先比較兩者的輸入／popup／CanvasLayer相容性，再固定一條正式路線，不保留兩套常駐後處理。

- 採用真正低解析合成後，退役現有僅針對世界的重複pixel shader。
- MSAA／FXAA／TAA關閉，沒有柔焦、景深或動態解析度；相機維持流暢，投影後的2D標記對齊像素格。
- Native Button／OptionButton仍負責輸入與焦點；下拉和tooltip也須在相同遊戲viewport中顯示，避免額外高清OS小視窗。
- 不用每幀改動頂點或UV去模擬「復古」。靜態物件的不規則是固定造型，不能隨鏡頭爬動。
- 原始大圖／GLB保留；交付衍生像素圖集及匯入規格。將主選單的紙紋簡化成可讀的網點，避免縮小後變成髒雜訊。

### 2.3 共通視覺規範

| 項目 | 初始規格 |
|---|---|
| 輪廓 | 一般1內部像素，角色／重要剪影1–2，技能主形狀2–3；依距離分級 |
| 色階 | 亮／暗2階，必要時加第3階高光；暗部用藍紫或深青 |
| 局部色盤 | 每材質約3–5色；同一擊主特效最多角色色＋奶油白＋墨色 |
| 貼圖 | 小物64–128²，牆面／車／植物128–256²，共用atlas256–512² |
| Texel density | 街景起始32–64px/m；重要大招／招牌獨立規格，避免比例跳躍 |
| 過濾 | Point；近景先無mip。遠景若閃爍，以低細節替代貼圖／離散mip比對解決，不加三線性模糊 |
| 動畫時間 | 判定／輸入保持60Hz；角色表演與特效可用12–18fps的清楚pose／cel |
| 輸出 | 預先確定像素尺寸；禁止任意縮放後留下半像素描邊或軟邊光暈 |

同一美術語言不等於所有物件同色：UI用橙／黃綠，街景保留藍樓／橙樓／暖灰路面，角色和技能保留流派色；共同的是墨線、色階、像素格和形狀節奏。

## 三、JSR式字體：建立真正的字體系統

原JSR字標包含客製字形；目前沒有證據可把某個網路下載字體稱作官方完整字族。新方向是做本作自己的**AFTERHOURS塗鴉字體／Sprite Font**，沿用已批准字標的語言。

| 用途 | 方案 | 規範 |
|---|---|---|
| Logo／頁面標題 | 客製尖角、粗斜體、奶油白外框、深紫陰影 | 先定稿FIGHT／FIGHTERS／TRAINING／SETTINGS／AI DEMO、PAUSE／RESULT |
| 動態大字／數字 | 共用英文字母與數字glyph atlas | 先做A–Z、0–9、基本標點與∞；相同字寬邏輯／基線／外框 |
| 小型說明／設定 | 易讀的窄體像素無襯線 | 內部字高10–12px起；不把正文也塞滿塗鴉尖刺 |

- 大標題可用24–40px內部字高；血量／時計約20–28px；實際字級以同場截圖驗收。
- 文字抗鋸齒／MSDF停用，使用原生bitmap字形或可控glyph atlas，整數字級、Nearest。
- 英文介面維持；Button仍有真正的名稱／焦點／鍵盤行為，動態數字由資料渲染，不能重新烘焙成固定100HP。
- Barlow可作排版過渡，不當最終「JSR字體」交差。正文候選與任何下載字體必須核實授權再admit；不假設網上標成JSR就可用。
- 先交一張包含五主選項、75／100／999／∞、HITS／BREAK／KO與設定正文的字樣表，再整體替換，避免逐頁用不同字。

## 四、不整齊、瑕疵與手繪感：用有設計的偏差

目標是「人手建成、被生活使用的街道」。固定建築結構、地面判定與可讀剪影；偏差放在裝飾、材質和輪廓節奏。

### 4.1 幾何與擺放

- 店舖雨篷：前緣2–3個不等長折角，單側稍下垂，不做均勻鋸齒。
- 冷氣／花盆／路牌：少量偏移3–10cm、旋轉1–3°；同類準備3–5個造型，不對每件一律亂轉。
- 大廈：主要柱／樓層對齊；局部窗台、外加鐵籠、封窗板、招牌支架不完全一致。視覺關鍵樓角只作很小的非對稱斜切。
- 路面：用畫在貼圖上的裂紋、補丁和邊緣缺角；斑馬線有缺漆，仍保留清楚走線。戰鬥碰撞面保持平坦。
- 電線：不同下垂幅度、束線厚度與接頭，形成有方向的線條，而不是整齊平行的裝飾格。
- 固定seed分配偏差，遠近鏡一致。視覺偏差不修改碰撞、命中範圍或道路可走區。

### 4.2 手繪材質

- 大色塊內用1–2塊刻意畫出的陰影／褪色，沿窗台、排水、貼紙邊出現污漬。
- 磚縫粗細和窗框線條有有限變化；空調下方畫垂直水痕，柱底有踢痕，路邊有輪胎擦痕。
- 裝飾線和貼紙陰影可錯位1px，主輪廓保持乾淨。這是局部印刷偏差，不是全畫面RGB分離。
- 約70%表面保持乾淨大色塊、20%使用痕跡、10%強個性細節；先作樣本評審，不把比例當硬演算法。
- 不加全域噪點，不把每條邊變波浪，不逐幀抖動整棟樓。空白招牌保持無文字，等使用者提供正式貼圖。

## 五、舊遊戲貼圖、垃圾與街頭細節

先做一組共用街道atlas：瀝青補丁、缺漆斑馬線、排水蓋、牆面水痕、鐵捲門、冷氣百葉、花盆、紙箱與垃圾。

初批資產：紙團、飲品罐、杯／吸管、小袋、折紙盒、報紙、瓶子、落葉，各2–3個變體。紙張是清楚的折角面；罐是6–8邊；表面細節畫在base color，沒有寫實金屬／粗糙度貼圖。

佈置成3–5個有原因的群落：垃圾桶旁、店舖牆腳、電線柱底、排水口、貨車卸貨處。代表畫面先約20–35個小物，核心斑馬線保持留白。少量可被風帶走的紙，其餘固定批次化。紙上無亂碼假新聞／品牌文字。

大多用無碰撞靜態裝飾；少數紙片用有界循環，不啟用幾十個剛體。每個細節須在640×360仍成為可辨識形狀，無法讀出的細碎線直接刪掉。

## 六、植物與樹木同樣納入美術規範

不能只把目前綠方塊換成寫實樹貼圖。

- 花槽：做3–5種鋸齒葉簇／寬葉剪影，大小、方向及缺葉位置有變化；每簇約3個色塊。
- 街邊樹：樹幹偏斜、有2–3個明確分叉；樹冠由5–9個不對稱低面數團塊構成，強調大輪廓與負空間。
- 小葉使用少量交叉面片與硬alpha clip，禁止柔邊半透明葉海。若要雙向可見，用可追溯的背面幾何，避免隨意全域關閉背面剔除。
- 葉片高光直接畫在貼圖／頂點色，陰影深青，沒有PBR濕亮反射。葉脈只留1–2條能讀到的線。
- 搖動是葉尖／枝條的簡單權重，不讓樹根滑動。起始幅度2–4°、週期2–4秒，固定相位差；不全街同步擺頭。
- 行人視線與招牌輪廓有優先權，樹冠不蓋住兩個角色的空中追擊區。

## 七、有生命的背景：像格鬥舞台一樣分層表演

新增一個背景動態調度器，統一控制頻率、畫面區域和事件優先級，避免每個物件各自倒數後同時動。

| 層級 | 內容與起始循環 | 視覺限制 |
|---|---|---|
| 常駐微動 | 電線／雨篷輕擺、植物、抽氣扇、很慢雲層；2–8秒各自不同 | 低幅度，動線不穿角色 |
| 生活循環 | 店主抹櫃台、路人看手錶／喝飲品、兩人閒談、卸貨工提箱；5–12秒 | 每人有獨立停頓，不齊步重複 |
| 稀疏事件 | 遠處紅車／小貨車駛過、有人從店門出現、單次飛機掠過；15–45秒 | 同時最多1個顯眼事件 |
| 戰鬥回應 | 大招風吹紙張、路人縮肩／後退、店主短暫探頭 | 接真事件，有20–30秒冷卻，普通拳不全街驚叫 |

第一批具體安排：左店主抹枱、右行人喝飲品、後方兩人閒談／看錶、遠處紅車慢駛、停泊白車偶爾尾燈變亮、雨篷與葉簇微擺、紙片短距離翻動。日間街燈只作少量壞燈／狀態變化，不整排閃白光；可用發光材質假光，不加大量動態燈。

既有飛機沿機頭飛行保留。既有天空漂移先保留，再比較用獨立雲片平移是否更自然；不為移雲而轉動太陽、建築或投影。天空／貼圖來源不無故換掉。

車輛從建築遮擋後出現，沿後巷固定路徑行駛，再在另一遮擋處回收；不得在鏡頭中央瞬移重置。前景主要白車／紅車等場景識別物不隨意刪走。新交通不進戰鬥跑道、不撞角色，不用改寫玩法來遷就裝飾。

### 時鐘與優先級

- 普通交戰背景按自己的1倍時間運行，不跟戰鬥釋放2倍一起狂飆。
- 重要全停／紅幕時暫停或遮住顯眼背景事件，保住蓄力張力；釋放後才觸發少量群眾反應。
- Esc／真正暫停：模擬與背景動畫停，設定UI仍可操作，音樂只duck並繼續播放。
- 選單有自己的UI時間，不卡在戰鬥慢鏡內。F2停用大位移／強閃與鏡頭，仍保留必要焦點、技能形狀和數值。
- 固定可重現的seed／事件時間表，提供凍結背景與指定事件的截圖工具。

## 八、UI動畫：讓貼紙與電台構圖活動

目前主選單是一整張圖，不能靠搖整張圖達成高品質動畫。下一步將底板、Logo、5個字牌、頻率游標、裝飾網點、背景人物拆為可追溯圖層，再按原構圖組回。盡量沿用來源，不重新發明版面。

| 事件 | 動作方案 | 起始時間 |
|---|---|---|
| 進主選單 | 字牌依序以2–3張清楚位置落入，Logo一次硬落點 | 全部約180–240ms，條目錯開30–45ms |
| 移動焦點 | 電台指針切到該選項，字牌位移1–2px＋角落短線 | 70–100ms |
| 點按 | 字牌壓1px、陰影收回，立刻給聲音與選取回饋 | 80–120ms，不延遲真正輸入 |
| 選角切換 | 角色先轉身／擺姿勢，名字標籤切入 | 約120–200ms，允許快速跳過／取消舊動畫 |
| 技能就緒 | 能量刻度一次短促亮起，沒有不停呼吸的光暈 | 2–3cel |
| 大字／KO | 字形撞入、一次撞擊幀再定住 | 按既有真事件時序，勿多個banner堆一起 |

不讓所有UI一直浮動。精準命中和正常交戰時，HUD大部分維持安靜；誇張集中在重要事件。Reduced effects保留立刻切色／邊框，取消抖動與大幅位移。

## 九、3D選角：真正模型＋專屬表演

右側改獨立透明背景3D預覽viewport：使用現有GLB、同套toon／描邊、同一像素尺度，合成在電台圓盤上。選角本身不啟動戰鬥模擬，不扣能量、不播攻擊音、不帶受擊閃白。

- 右側建議約280px內部高度，保持腳底基線、身高關係與安全留白；角色4仍略矮，不把每人自動縮放成一樣高。
- 3/4角度，臉、手、鞋皆可讀；模型可作有限轉向，不不停自轉。圓盤指針是介面標記，不穿過人物身體。
- 選取P1或P2時預覽該方；卡片及名稱立刻更新，非同步動作不能在快速切角時跳回舊角色。
- 4張小卡也改不同pose。先用同一模型離屏擷取，未選卡可靜止或8fps局部循環，主預覽12–18fps；不用5個視窗都60fps帶昂貴陰影。
- 卡片提供原生Button名稱、焦點和P1/P2標記；圖像不是唯一操作或唯一身份訊號。

### 四人pose設計

| 角色 | 選角入場／待機 | 確認動作 | 臉部與剪影重點 |
|---|---|---|---|
| 原角色／拳手 | 單手拉手套、另一手叉腰，重心微偏；再短暫展開拳架 | 一記乾脆直拳後收手 | 至少一側臉完整可見，手不長時間遮鼻眼 |
| 角色1／舞者 | 側身拍肩、腳尖點地或小幅heel-toe換步 | 短旋踢／街舞定格 | 長腿形成斜線，手臂展開，與拳手完全不同 |
| 角色3／重拍 | 穩定寬站、單手壓指節或雙臂放鬆交叉 | 一次跺腳／肩部重擺，短促聲波 | 大輪廓穩重；避免兩手聚在臉前 |
| 角色4／電光 | 調護目鏡、抬下巴、單膝彈一下再站穩 | 向前短踏步配鋸齒軌跡 | 露出護目鏡／眼睛；不再深蹲成過小身形 |

每人做「入場、待機、確認、卡片定格」四種狀態。動作來源先評估現有CC0 clips與程序骨骼，再補必要關鍵姿勢；外部來源如Mixamo需確認能取得和適用授權，沒有登入／下載就不列作已取得。

快速連選時，每次取消上一個pose transition，回收舊模型材質／viewport；連續切角100次檢查，不允許模型、陰影或特效越疊越多。

## 十、更大、更誇張的技能：放大構圖，不放大雜訊

特效以同一640×360畫布的內部像素規劃：

| 等級 | 建議主形狀尺寸 | 演出方式 |
|---|---|---|
| 輕攻擊 | 約32–56px | 小命中核、清楚方向、短收尾 |

這是初始尺寸，按鏡頭距離縮放；不能讓正常一拳也像全屏大招。hitbox／傷害不因裝飾變大而自動增加，接觸核永遠在實際命中處，外延是可辨識的美術延伸。

四種語言繼續保留並加強：拳手長拳壓力線、舞者寬雙弧、重拍低頻角形波、電光鋸齒折線。單次重要命中最多一個主形狀、一個亮核及少量收尾；不重新疊回被淘汰的生成圖、假煙霧和棒狀骨架殘影。

可用6–8cel sprite／mesh動畫或現在的向量cels，但都在低解析層輸出；不用GIF當引擎特效格式，避免透明、幀率和壓縮不可控。GIF只作審稿預覽。

維持「蓄力收縮→全停／慢鏡→大範圍釋放→迅速清場」的對比。全屏效果不長時間遮住血量、腳底及反擊線索；強演出結束，城市和HUD必須乾淨還原。

## 十二、效能、清理與證據

- 靜態建築、垃圾、植物沿現有批次化；動畫物件從靜態批次中獨立，不能把整條街改成每幀逐件更新。
- 稀疏事件用pool，限制同時可見數量；遠景路人用低頻更新，燈多用材質而不是新shadow light。
- 3D預覽只在選角頁活動，離頁停止／釋放；不在正式對戰背景偷偷渲染5個選角viewport。
- 不在軟體GL憑感覺宣稱60fps。記錄同一場景前後GPU／CPU時間、draw calls、節點、活動特效和viewport數；目標設備上才驗收實際效能。
- 對13招、4角色、UI狀態、背景循環、pause／F2／restart／退出做可重現擷取；不覆寫歷史證據。
- 保留既有37項UI／音樂行為核心，按新3D卡片擴充，而不是把視覺截圖當成功能驗證。
- 本輪只有計劃文件，沒有更換runtime、下載新動作、生成新資產或更新公開Web。
